# RhythmGame（SDL3 / C++17）

4 レーン落下型のリズムゲームです。
通常ノーツとロングノーツに対応し、判定ごとに演出が変わります。

## 必要な環境

- Windows
- Visual Studio 2022 以降（「C++ によるデスクトップ開発」ワークロード）
- CMake 3.24 以降
- Git（SDL3 の取得に使用）
- インターネット接続（初回の CMake 実行時に SDL3 をダウンロードするため）

## ビルドと実行

```powershell
cmake -S . -B build
cmake --build build --config Release
build\Release\RhythmGame.exe
```

- SDL3（release-3.4.18）は CMake が自動でダウンロードし、静的リンクします。DLL のコピーは不要です。
- 初回のみ SDL のビルドに数分かかります。
- ビルド後、`assets/` が実行ファイルの隣に自動でコピーされます。
- Visual Studio で「フォルダーを開く」から CMakeLists.txt を開いてもビルドできます。
- Ninja でビルドした場合、実行ファイルは `build\RhythmGame.exe` にできます。

## 操作

| キー | 動作 |
| --- | --- |
| D F J K | 各レーン |
| ↑ / ↓ | 判定オフセット ±5ms（音より早く/遅く感じる時に調整） |
| A | オートプレイ切り替え |
| R | リスタート |
| Esc | 終了 |

## ゲームのルール

### 判定とスコア

ノーツの時刻とキーを押した時刻のずれで判定します。

| 判定 | ずれ | スコア | 演出 |
| --- | --- | --- | --- |
| PERFECT | ±33 ms 以内 | 1000 | 金色の光の粒と広がる枠。判定文字が拡大するアニメーション |
| GREAT | ±66 ms 以内 | 700 | 水色の光の粒と広がる枠 |
| GOOD | ±100 ms 以内 | 300 | 緑色の小さく広がる枠 |
| MISS | 見逃し | 0 | レーンが赤くにじみ、判定文字が震える。コンボが途切れる |

判定にはキーを押した瞬間のタイムスタンプを使うため、フレーム待ちによる遅れは判定に影響しません。

### ロングノーツ

- 始点は通常ノーツと同じように、押したタイミングで判定します。
- 終点まで押し続ければ PERFECT です。早く離した場合は終点とのずれで判定し、GOOD の幅より早ければ MISS です。
- 始点を逃すと終点も MISS になります（1 本で 2 回判定）。

## 構成

```text
src/
  main.cpp          エントリポイント。SDL 初期化・ウィンドウ作成・メインループ
  Config.h          画面サイズ・レーン配置・スクロール速度・キー割り当て・演出時間などの定数
  AudioClock.h/.cpp 曲の再生と、再生位置を基準にしたゲーム内時計
  Chart.h/.cpp      ノーツの定義と譜面ファイルの読み込み
  Judge.h/.cpp      判定の種類・判定幅・スコアとコンボの集計
  Game.h/.cpp       ゲーム進行（キー入力・判定・ロングノーツ・オートプレイ）
  GameRender.cpp    描画（レーン・ノーツ・判定演出・HUD・リザルト画面）
assets/
  song.wav          曲（WAV 形式）
  chart.txt         譜面
tools/
  make_sample.py    サンプル曲と譜面を生成するスクリプト
```

### 仕組みのポイント

- **時計は曲の再生位置**：ゲーム内の時刻は、オーディオデバイスに渡した音声データの量から求めます。音とノーツがずれません。
- **ノーツの位置は毎フレーム計算**：判定ラインからの距離 =（ノーツの時刻 − 現在の時刻）× スクロール速度。フレームレートが変わっても誤差が積み重なりません。

## 譜面の書き方

`assets/chart.txt` は 1 行に 1 ノーツを書きます。`#` で始まる行はコメントです。

```text
# 時刻(ms) レーン(0〜3) [終点の時刻(ms)]
1714.3 2
2142.9 1 3428.6
```

- 1 行目は通常ノーツ、2 行目は 2142.9 ms から 3428.6 ms まで押し続けるロングノーツです。
- レーンは左から 0, 1, 2, 3（D F J K）です。
- 3 列目を書くとロングノーツになります。
- 行の順番は自由です（読み込み時に時刻順に並べ替えます）。
- BPM が分かれば、拍の位置は `60000 / BPM × 拍数` ms で求められます。

## 自分の曲で遊ぶ

1. 曲を WAV に変換して `assets/song.wav` に置く
2. `assets/chart.txt` にノーツを書く
3. ビルドし直す（assets が exe の隣にコピーされます）

## サンプル曲と譜面の再生成

`tools/make_sample.py` は、140 BPM・約 30 秒のサンプル曲（`song.wav`）と、それに合わせた譜面（`chart.txt`、ロングノーツ入り）を生成します。
ゲームの実行には不要で、サンプルを作り直したいときだけ使います。numpy が必要です。

```powershell
py -m pip install numpy
py tools/make_sample.py
```

実行すると `assets/` の 2 ファイルが上書きされます。乱数のシードを固定しているので、何度実行しても同じ結果になります。

## 開発用オプション

```powershell
RhythmGame.exe --shot 15000
```

オートプレイで再生し、指定した時刻（ms）の画面を `shot.bmp` に保存して終了します。表示の確認に使います。
